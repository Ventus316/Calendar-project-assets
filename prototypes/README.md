# 版面原型（已放棄的設計方向）

日曆版定案前試過的另一種呈現：把 32 集做成像影音平台選集列的滑動卡片，滑到焦點位置的那一集放大，兩旁縮小變暗，點旁邊的卡片會自動滑到中央。

- `story_horizontal.html`：橫向滑動
- `story_vertical.html`：直向滑動，卡片可放劇照背景

這兩頁的文案是當時另外試寫的版本，不是正式資料，正式內容以 `assets/js/data.js` 為準。

## 為什麼放棄

滑動停下來、要定格在某一集時，卡片總會晃一下或停偏，呈現不夠流暢。回頭看程式，主要原因有三個：

1. 每一幀都改卡片的 `margin`，版面寬度跟著變，焦點位置一直在移動。
2. 同一幀裡對 32 張卡片輪流「量位置、改樣式」，每張都強制瀏覽器重排一次。
3. 手動滑完沒有對齊機制，只有點卡片才會自動置中。

## 已重做

正式版在根目錄的 `story.html`，做法就是下面三點。這兩頁保留當作對照。

## 重做的方向

- 用 CSS `scroll-snap-type: x mandatory` 加 `scroll-snap-align: center`，交給瀏覽器對齊。
- 縮放只用 `transform`，不改 `margin`，版面就不會動。
- 每張卡片的縮放直接用捲動位置和卡片序號算，不用每一幀量位置。
